---
name: saxon-algebra-1-grader
description: Grades a student's handwritten answers on a printed Saxon Algebra 1 problem set made by the saxon-algebra-1 skill. Reads a scanned PDF or photos (JPEG/PNG/HEIC) of the solved sheet, matches it to its answer key by the set ID in the page footer (using Saxon_Algebra1_Catalog.json), scores each final answer as correct, wrong or [Check] when the handwriting is unclear, and produces a graded report PDF with the score, what was read for each question and short notes on mistakes. Use when the user asks to grade, score, mark or check a solved problem set, worksheet or homework, or uploads a scan or photo of a problem set the student has filled in by hand.
---

This skill grades a problem set that was generated by the `saxon-algebra-1`
skill, printed, solved by hand, and then scanned or photographed. It does
not solve book pages (that is the `saxon-algebra-1` skill's Mode B).

Whenever this file says "ask", ask all the questions due at that point
together in one turn (use a structured multiple-choice prompt if your
environment has one, such as Claude Code's AskUserQuestion tool; otherwise
ask them in plain text in a single message). Never ask a question the user
already answered in their request, or answered earlier in this conversation.

# Step 1: Get the scan

- Accept a scanned PDF (one or more pages) or one image per page (JPEG, PNG,
  HEIC, ...). The user may give file paths, attach or upload files, or paste
  images into the chat. If pasted, look for a local cached copy using
  whatever your environment provides (for example, Claude Code caches pasted
  images under `~/.claude/image-cache/`).
- Look at every page directly; you read handwriting from the page images
  yourself. No OCR tool is needed. For a PDF, view each page as an image.
- Never move, rename or delete the user's original files.
- If a page is too blurry, dark, cropped or rotated to read, say which page
  and ask for a better scan of it before grading (a phone scanner app, page
  flat, good light, all four edges and the footer visible). Grade the
  readable pages only if the user says to go ahead.

# Step 2: Find the answer key

1. **Find the catalog** `Saxon_Algebra1_Catalog.json`: one the user uploaded
   in the chat, or the one in the `Saxon Algebra 1` folder (the folder that
   contains `Saxon_Algebra1_Concept_Guide.pdf`). Search for it the same way:
   the current working directory, a `Saxon Algebra 1` folder inside it, then
   the user's home folder (about 4 levels deep, skipping hidden and system
   folders such as `Library`). That folder is the **base folder**.
2. **Read the set ID** from the footer of the scanned pages
   (`Set L34-2026-11-19-01 · Page 1 of 3`) and find the matching
   `problem_sets` entry. Check that all pages carry the same ID and that no
   question page is missing (compare with `question_pages`). If pages are
   missing, tell the user which, and ask whether to grade the rest.
3. **If the footer cannot be read or there is no ID** (an older sheet), use
   the lesson number in the title and the question wording to find the set
   in the catalog. If more than one set could match, list them and ask.
4. **Answer key:** use the entry's `answers`. If the entry has no `answers`
   (an older set), use the solutions section of the original PDF if it has
   one; otherwise work out each answer from the stored question text and
   verify it with code (for example Python with sympy or fractions). Say in
   the report which source was used.
5. **If no catalog or set can be found,** ask the user for the catalog file
   or the original problem set PDF. As a last resort, and only if the user
   agrees, read the questions from the scan itself, solve them with code,
   and grade against that, noting it in the report.

Also read the concept guide entry for the lesson if it is available, to
know whether the lesson requires answers in simplest form and to word the
mistake notes the way Saxon teaches.

# Step 3: Ask before grading

In one turn, ask:

1. **Grading style:**
   - "Final answer only" (recommended): each question is right or wrong
     based on what is on the Answer line;
   - "Final answer plus work": also look at the work shown and give half
     credit when the method is right but there is a small slip (for example
     an arithmetic error in the last step).
2. **Where should the report go?**
   - the usual folder, shown with its full path:
     `<base>/Graded YYYY-MM-DD/` (only when there is a base folder);
   - another folder on the computer (the user gives the path);
   - "Don't save to my computer; give me a download".

Do not ask about the set if Step 2 found it with certainty; just say which
set you are grading (ID, lesson and title).

**Download mode:** produce the report through whatever download mechanism
the environment has (for example, in the Claude app, write it to the outputs
folder). If the environment has no way to hand over a download (for example
Claude Code in a terminal), say so and offer a temporary folder or a folder
of their choice. In download mode, write nothing to the user's computer
except the catalog update in the base folder (if there is one). If there is
no base folder, hand over the updated catalog as a download too and remind
the user to upload it next time.

**Files never overwrite:** if a name is taken, add `_01`, `_02`, ... before
the extension.

# Step 4: Read each answer

For each question 1 to Q:

- Find the student's final answer: what is written on the `Answer:` line.
  If that line is empty, look for a clearly final answer at the end of the
  work (boxed, circled, or the last line) and note "answer not on the
  Answer line". If there is no answer at all, the question is **Blank**.
- Write down exactly what you read, character by character, as the
  student wrote it (for example `x = -3/4`). This goes in the report so the
  parent can compare it with the paper.
- **Handwriting confidence.** Watch for the usual confusions: 1 / 7, 4 / 9,
  5 / S, 2 / z, 0 / 6, x / × (times), a minus sign vs a dash or stray mark,
  a fraction bar vs a minus sign, exponents vs normal digits, and decimal
  points vs specks. If any character that changes the result could be read
  more than one way, mark the question **[Check]** and give both readings.
  Never quietly pick the reading that makes the answer correct (or wrong).
- If "Final answer plus work" was chosen, also read the work and note where
  it goes wrong.

# Step 5: Score

Compare each answer with the key **using code**, not by eye: parse the
student's answer and the key (for example with sympy) and test whether they
are mathematically equal.

- **Correct:** equal to the key, or matches one of its `accept` forms.
  Equivalent forms count (`1/2`, `0.5`, `2/4`, `x = 5`, `5`), except:
  - if `simplest_form_required` is true (or the lesson's key rule is about
    simplifying), an equal but unsimplified answer is **Wrong** with the note
    "correct value, but not in simplest form";
  - units: on word problems, a correct number with missing or wrong units is
    still **Correct**, with a note about the units.
- **Wrong:** not equal to the key.
- **Blank:** nothing written. Scores 0.
- **[Check]:** handwriting unclear. Score it under the most likely reading,
  but list it separately so the parent can confirm, and say how the score
  changes if the other reading is right.
- **Half credit** (only with "Final answer plus work"): right method, small
  slip. Scores 0.5.

Score = correct (plus half credits) out of Q, and a percentage rounded to the
nearest whole number.

# Step 6: Write the graded report PDF

- **File name:** `Lesson<N>_Graded_<YYYY-MM-DD>.pdf` (today's date), plus
  `_01`, `_02`, ... if taken.
- **Location:** as chosen in Step 3. For the usual folder, create
  `<base>/Graded YYYY-MM-DD/` if needed and also copy the scan file(s) there
  as `Lesson<N>_Scan_<YYYY-MM-DD>.<ext>` (`_p1`, `_p2`, ... for separate page
  images). In download mode, do not copy the scans anywhere.
- **Layout (letter size, black on white):**
  - Title "Lesson N Graded", the lesson title, the set ID, the date graded,
    the grading style, and the scan file name(s).
  - The score in large type: `Score: 13 / 15 (87%)`.
  - If any question is [Check], a line under the score: "Questions marked
    [Check] were hard to read; please compare them with the paper. If a
    reading is wrong, ask to regrade."
  - A table with one row per question: number, the question (shortened if
    long), what the student wrote (as read), the correct answer, result
    (Correct / Wrong / Blank / Half / [Check]) and a short note.
  - **Mistakes to review:** for each wrong or half-credit question, one or
    two sentences on what went wrong and the correct step, in plain words a
    student can follow, using the lesson's key rule from the concept guide.
  - Real superscripts and proper fractions, not `^`.

# Step 7: Update the catalog and reply

Add an entry to the catalog's `gradings` list (create the list if it is
missing) and save the catalog:

```json
{
  "set_id": "L34-2026-11-19-01",
  "lesson": 34,
  "graded": "2026-11-21",
  "style": "final_answer",
  "score": 13,
  "out_of": 15,
  "percent": 87,
  "results": [
    {"n": 1, "read": "x = 5", "result": "correct"},
    {"n": 2, "read": "x = -4 or x = -9", "result": "check", "note": "4 or 9 unclear"}
  ],
  "report_file": "/full/path/to/Lesson34_Graded_2026-11-21.pdf",
  "scan_files": ["/full/path/to/Lesson34_Scan_2026-11-21.pdf"],
  "delivery": "saved"
}
```

If the same set was graded before, keep the old entry and add the new one
(for example after a regrade or a second attempt).

Then tell the user:

- the score (and percentage);
- the questions that were wrong or blank, each with the correct answer;
- every [Check] question, with what you read and the other possible
  reading, and how the score would change;
- where the report is (full path, or that it is ready to download);
- if earlier gradings exist for the same lesson, one line comparing them
  (for example "Lesson 34: 9/15 on Nov 12, 13/15 today").

**Regrading:** if the user says a reading was wrong (for example "question 4
says 7, not 1"), fix that reading, rescore, write a new report (with the next
`_01` suffix), and add a new `gradings` entry noting the correction.
